## Q1：Flow Transport 能不能暴露迁移攻击的共享方向？

这是最重要的 observation。

设：

\[
\Phi_k=\Phi_{r_k\rightarrow t_k}
\]

表示第 \(k\) 个 finite-time Flow Map。Flow Map Matching 本身提供的正是 two-time transport map；MeanFlow 则提供有限区间 average velocity，因此这两个技术天然适合构造这种 manifold probing，而不像普通 FM 只给瞬时 velocity。[arXiv](https://arxiv.org/abs/2406.07507?utm_source=chatgpt.com)

对于每条 transport trajectory：

\[
X_k=\Phi_k(X)
\]

获得 adversarial direction：

\[
g_k
=
J_{\Phi_k}(X)^T
\nabla_{X_k}
\mathcal L(f_s(X_k),y).
\]

于是：

\[
G(X)=\{g_1,\ldots,g_K\}.
\]

我们的第一个核心发现应该是：

\[
\boxed{
\operatorname{Stability}_{Flow}(d)
\uparrow
\quad\Longrightarrow\quad
\operatorname{Alignment}(d,g_t)
\uparrow
}
\]

其中 \(g_t\) **只用于研究阶段验证，攻击阶段绝对不可访问 target model**。

这是非常重要的实验设计，否则 reviewer 会怀疑信息泄漏。

# Q2：Flow 下什么东西保持 invariant？

这里不要把 PCA 当贡献。

我建议最终方法改成一个更漂亮的：

## **Adversarial Parallel Transport Consistency — APTC**

核心关系：

\[
\boxed{
d(\Phi_k(X))
\approx
J_{\Phi_k}(X)d(X)
}
\]

左边：

> 到达新的 manifold point 后重新得到的攻击方向。

右边：

> 原始攻击方向经过 Flow Map Jacobian transport 后应该到达的位置。

如果：

\[
d(\Phi_k(X))
\approx J_{\Phi_k}(X)d(X)
\]

对多个 \(k\) 都成立：

\[
\forall k\in\{1,\ldots,K\},
\]

我们就认为 \(d\) 是：

\[
\boxed{\text{Flow-Invariant Adversarial Direction}}
\]

定义：

\[
\mathcal L_{\mathrm{inv}}
=
\frac1K
\sum_k
\left[
1-
\cos
\left(
d(\Phi_k(X)),
J_{\Phi_k}d(X)
\right)
\right].
\]

这比：

> MeanFlow + cosine gradient ensemble

高级很多。

因为你真正定义了：

### **什么叫 adversarial direction 在 video manifold 上稳定。**

# Q3：视频为什么需要额外处理？

因为 spatial/manifold invariance 不等于 temporal transferability。

因此只加**一个 video-specific module**：

## **Temporal Semantic Transport — TST**

不要 optical flow。

取一个 frozen video/self-supervised encoder 的 token：

\[
F^\tau.
\]

跨帧 correspondence：

\[
A_{\tau\rightarrow\tau+1}
=
\operatorname{Softmax}
\left(
\frac{F^\tau F^{\tau+1T}}{\sqrt d}
\right).
\]

攻击方向满足：

\[
d^{\tau+1}
\approx
A_{\tau\rightarrow\tau+1}^{T}
d^\tau.
\]

于是：

\[
\mathcal L_{\mathrm{temp}}
=
\sum_{\tau}
\left[
1-
\cos
(
d^{\tau+1},
A_{\tau\rightarrow\tau+1}^{T}d^\tau
)
\right].
\]

物理意义非常清楚：

> **攻击方向不是粘在 pixel coordinate 上，而是沿着动作语义运动。**

这样才真正区别于 image AdvFM。

AdvFM 已经证明 velocity-field attack 可以通过 smoothing、trajectory optimization 等获得更好的 image black-box transfer，因此你不能再把“Flow improves transferability”本身当贡献；你必须把 novelty 放到 **Flow Transport → invariant manifold direction → video temporal transport**。[Open Access CVF](https://openaccess.thecvf.com/content/CVPR2026/html/Liu_AdvFM_Lookahead_Flow-Matching_Velocity-Field_Attacks_for_Imperceptible_and_Transferable_Adversarial_CVPR_2026_paper.html?utm_source=chatgpt.com)

# 四、我建议把“Manifold”定义得非常谨慎

CVPR reviewer 很可能攻击这一点：

> “You claim a manifold, but where is the manifold?”

所以不要把：

\[
\mathcal M_{adv}
\]

随便定义成 gradient collection。

定义：

\[
\boxed{
\mathcal M_{\mathrm{TA}}
=
\left\{
X+\delta:
\|\delta\|_p\le\epsilon,\;
\mathcal I_F(\delta)\ge\gamma_F,\;
\mathcal I_T(\delta)\ge\gamma_T
\right\}
}
\]

其中：

\[
\mathcal I_F
=
\frac1K
\sum_k
\cos
\left(

是 **Temporal Transport Invariance**。

于是：

\[
\boxed{
\mathcal M_{\mathrm{TA}}
=
\text{Transferable Adversarial Flow Manifold}
}
\]

就是：

> 同时满足 flow transport stability 和 temporal transport stability 的 adversarial neighborhood。

这样“manifold”不是一句 marketing language。
